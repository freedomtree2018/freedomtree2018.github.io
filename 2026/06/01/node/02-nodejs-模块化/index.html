Node.js学习指南-模块化

Posted on 2026-06-01 Edited on 2026-06-03

1. 模块化基础概念

1.1 什么是模块化

模块化是指解决一个复杂问题时，自顶向下逐层把系统划分成若干模块的过程。对于整个系统来说，模块是可组合、分解和更换的单元。

在编程领域，模块化就是遵守固定的规则，把一个大文件拆成独立并互相依赖的多个小模块。

1.2 模块化的好处

  • 提高代码复用性
  • 提高代码可维护性
  • 支持按需加载

1.3 模块化规范

模块化规范就是对代码进行模块化拆分与组合时需要遵守的规则：

  • 规定使用什么语法格式来引用模块
  • 规定在模块中使用什么语法格式向外暴露成员

这样做的好处是：降低沟通成本，方便模块间相互调用。

2. Node.js 中的模块化

2.1 模块的分类

Node.js 根据模块来源，将模块分为三类：

  • 内置模块：Node.js 官方提供，如 fs、path、http 等
  • 自定义模块：用户创建的每个 .js 文件，都是自定义模块
  • 第三方模块：由第三方开发，需先下载才能使用

2.2 加载模块：require()

2.3 模块作用域

2.3.1 什么是模块作用域

和函数作用域类似，在自定义模块中定义的变量、方法等成员，只能在当前模块内被访问，这种模块级别的访问限制，叫做模块作用域。

2.3.2 模块作用域的好处

  • 防止全局变量污染

2.4 向外共享模块成员

2.4.1 module 对象

每个 .js 自定义模块中都有一个 module 对象，存储了和当前模块有关的信息：

2.4.2 module.exports 对象

在自定义模块中，可以使用 module.exports 将成员共享出去。外界用 require() 导入模块时，得到的就是 module.exports 指向的对象。

2.4.3 共享成员的注意点

require() 导入模块时，结果永远以 module.exports 指向的对象为准。

2.4.4 exports 对象

为了简化代码，Node 提供了 exports 对象：

  • 默认情况下，exports 和 module.exports 指向同一个对象
  • 最终共享结果，还是以 module.exports 指向的对象为准

2.4.5 exports 与 module.exports 的使用误区

常见情况及导出结果：

代码示例 导出结果
exports.username = 'zs'; module.exports = { gender: '男', age: 22 } { gender: '男', age: 22 }
module.exports.username = 'zs'; exports = { gender: '男', age: 22 } { username: 'zs' }
exports.username = 'zs'; module.exports.gender = '男' { username: 'zs', gender: '男' }

建议：不要在同一个模块中同时使用 exports 和 module.exports，以避免混乱。

2.5 CommonJS 模块化规范

Node.js 遵循 CommonJS 规范，规定如下：

  • 每个模块内部，module 变量代表当前模块
  • module 变量是一个对象，它的 exports 属性（即 module.exports）是对外的接口
  • 加载某个模块，其实是加载该模块的 module.exports 属性，require() 方法用于加载模块

3. npm 与包

3.1 包

3.1.1 什么是包

Node.js 中的第三方模块又叫做包。就像“电脑”和“计算机”是同一个意思，包和第三方模块也是同一个概念，只是叫法不同。

3.1.2 包的来源

不同于 Node.js 中的内置模块与自定义模块，包是由第三方个人或团队开发出来的，免费供所有人使用。

注意：Node.js 中的包通常是免费且开源的，不需要付费即可下载使用。

3.1.3 为什么需要包

由于 Node.js 的内置模块仅提供了一些底层 API，项目开发时效率较低。
包是对内置模块的进一步封装，提供更高级、更方便的 API，大幅提升开发效率。

3.1.4 从哪里下载包

npm, Inc. 旗下的网站 https://www.npmjs.com/ 是全球最大的包共享平台。
包的真实下载地址是 https://registry.npmjs.org/。

说明：

  • 在 https://www.npmjs.com/ 上搜索包
  • 从 https://registry.npmjs.org/ 下载包

3.1.5 如何下载包

npm 的包管理工具会随着 Node.js 安装一起安装。
可以在终端中执行npm -v 命令，来查看npm包管理工具的版本号：

3.2 npm 初体验

3.2.1 格式化时间的传统做法

  • 创建格式化时间的自定义模块
  • 定义格式化时间的方法
  • 创建补零函数
  • 从自定义模块导出格式化时间函数
  • 导入该模块并调用函数

3.2.2 格式化时间的高级做法

  1. 使用 npm 包管理工具，在项目中安装格式化时间包 moment
  2. 使用 require() 导入该包
  3. 参考 moment 官方 API 文档进行格式化

3.2.3 安装包命令

3.2.4 安装后新增文件

初次安装包后，项目目录下会新增：

  • node_modules 文件夹：存放已安装的包
  • package-lock.json：记录依赖详细信息（包名、版本、下载地址等）

注意：不要手动修改 node_modules 或 package-lock.json，npm 会自动维护它们。

3.2.5 指定版本安装

3.2.6 语义化版本规范

版本号形式为 X.Y.Z：

  • X：大版本
  • Y：功能版本
  • Z：Bug 修复版本

规则：前一位升级时，后面位数归零。

3.3 包管理配置文件

3.3.1 package.json 作用

package.json 是 npm 项目根目录必须存在的配置文件，用于记录：

  • 项目名称、版本、描述
  • 项目依赖的包
  • 开发依赖与生产依赖

3.3.2 多人协作问题

node_modules 文件夹体积庞大，通常不纳入版本控制。
团队共享代码时，只需保留 package.json 和 package-lock.json，然后执行依赖安装。

  • 目录名建议为英文，避免中文和空格
  • 安装包时，npm 会自动写入 package.json

3.3.4 一次性安装所有依赖

原理：npm 读取 package.json 中的 dependencies 字段，批量下载依赖。

3.3.5 卸载包

卸载后，npm 会自动从 dependencies 中移除该包记录。

3.3.6 devDependencies 节点

  • dependencies：生产依赖，开发与上线都需要
  • devDependencies：开发依赖，仅本地开发使用，上线时不需要

3.4 解决下载依赖速度慢的问题

3.4.1 为什么下载慢

默认从国外 https://registry.npmjs.org/ 下载，网络传输路径较长，导致速度慢。

3.4.2 淘宝 NPM 镜像服务器

淘宝搭建了国内镜像，同步官方 npm 数据，国内下载速度更快。

3.5 包的分类

3.5.1 项目包

安装到项目目录的包称为项目包，分为：

  • 开发依赖包：npm i 包名 -D，写入 devDependencies，仅开发阶段使用
  • 核心依赖包：npm i 包名，写入 dependencies，开发与线上都需要

3.5.2 全局包

加 -g 参数即为全局安装，默认路径（Windows）：C:\Users\用户目录\AppData\Roaming\npm\node_modules

注意：

  • 只有工具类包适合全局安装（提供终端命令）
  • 是否全局安装以官方文档为准

3.6 规范的包结构

规范的包必须满足三条规则：

  • 包独立存放在单独文件夹内
  • 包根目录必须存在 package.json
  • package.json 必填字段：name、version、main

参考文档：https://yarnpkg.com/zh-Hans/docs/package-json
